# v3 sing-box validation snapshot

This is an unofficial compatibility snapshot, not an official Remnawave v3 release. There is no
official v3 release tag to copy across the four repositories. Each repository keeps its own
upstream version source and publishes only its maintained `singbox` branch.

## Version sources

| Component | Version source | Snapshot value |
| --- | --- | --- |
| Panel | `@remnawave/docs/package.json` | `0.0.1` (documentation package; not a runtime panel version) |
| Backend | Root `package.json` | `3.0.0`, image metadata `3.0.0-singbox` |
| Frontend | Root `package.json` after the official v3 merge | `3.0.0` |
| Node | Root `package.json` | `2.8.0`, image metadata `2.8.0-singbox` |

Node has no official `3.0.0` in the synchronized upstream source, so this snapshot does not
invent one.

## Validation status

The local gates for this snapshot are:

- Frontend: `npm ci`, `npm run typecheck`, `npm run check`, and `npm run start:build` passed.
- Panel: `npm ci`, `npm run typecheck`, and `npm run build` passed; Docusaurus emitted only
  existing documentation warnings.
- Backend: `npm ci`, `npm run build`, `npm run build:seed`, `npm run validate:seed-core-inbounds`,
  `npm run validate:shadowrocket-anytls`, and `npm run check` passed.
- Node: `npm ci`, `npm run build`, `npm run trace`, and `npm run check` passed.

The four upstream synchronization workflows fail safely on merge conflicts, upload a readable
conflict report, and push only after repository validation and any applicable image build finish.
